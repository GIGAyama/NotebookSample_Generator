## 1. 貼る前に直すところ

**連載番号が `#◯` のままです。** 記事タイトルの `#◯` を実際の番号に置きかえてください。
推測で埋めると連載が壊れるので、あえて空けてあります。

それ以外は、そのまま貼れる状態です。

---

## 2. note への貼りかた

1. note の記事作成画面を開き、記事本文の 1 行目（`# 教室で使えるかもしれないもの作り …`）を
   **タイトル欄** に貼ります。行頭の `#` は外してください。
2. 残りの本文を、そのまま本文欄に貼ります。`##` の見出しは note 側で見出しとして認識され、
   目次が自動で作られます。
3. **画像は手動でアップロードします。** 本文中の `![…](images/xx-….png)` の行を、
   その位置で画像ブロックに差し替えてください。ファイル名の番号順にそのまま並んでいます。
4. 画像の直後にある 1 行の説明は、note の **キャプション欄** に移してください。
   本文に残したままでも読めますが、キャプションに入れたほうが収まりがよくなります。
5. ハッシュタグ欄の候補。`#GIGAスクール` `#教育ICT` `#小学校` `#ノート指導` `#板書`
   `#働き方改革` `#個別最適な学び`

## 5. 撮影中に確かめた動作

撮影は受け入れテストも兼ねています。記事で紹介した機能は、すべて実際に操作して動作を確認しました。
**壊れている機能は見つかりませんでした。** 記事と別に先出しすべき修正はありません。

確認した範囲は次のとおりです。

- テンプレート 5 種の切りかえ（マス数・行数・縦横・紙の向きが連動すること）
- カスタムのマス数・行数・文字サイズ・マス目の種類・ヘッダーの切りかえ
- 記号による装飾（丸囲み・青枠・赤枠・赤線・赤字・穴埋め・太枠・片側の太線・図形・日付マス・2桁数字）
- プレビューをドラッグしての選択と、ツールバーからの穴埋め適用（入力欄へ記号が自動で書き戻ること）
- 書き分けの警告（漢字の分断を 1 件検知し、該当行が一覧に出ること）
- 2 ページへの自動送り、原稿用紙 400字での 2 ページ送り
- 支援モード 3 種の切りかえ
- ノートの保存・一覧表示・呼び出し（別の文章に打ちかえたあと、保存した内容へ戻ることを確認）
- バックアップ出力（`notebook_data_backup.json` が実際に落ちてくること）
- 画像保存（`notebook-sample_<時刻>.png` が実際に落ちてくること）
- F1 のショートカット一覧、スマートフォン幅での設定ドロワー

押していないのは「印刷・PDF」だけです。ブラウザの印刷ダイアログが開いて自動操作が止まるためで、
機能そのものは印刷用のスタイル定義から全ページ出力になることを確認しています。

## 6. 撮り直すときの手順

```bash
npm i --no-save playwright
npm run build
node <skill>/scripts/serve.mjs dist 4180 /NotebookSample_Generator/   # 別ターミナル
node <skill>/scripts/capture.mjs shots.mjs \
  --base http://127.0.0.1:4180/NotebookSample_Generator/ --out shots
```

撮影用のシナリオ（`shots.mjs`）はリポジトリに残していません。撮り直すときは書き直しになります。
書くときに引っかかったところを 3 つだけ残しておきます。

1. **ヘッダーのトグルは文字で押せません。** ラベルの「ヘッダー」とチェックボックスが
   結びついていないので、`aside input[type=checkbox]` を直に押す必要があります。
   文字で押そうとすると、何も起きないまま次の画面へ進んでしまいます。
2. **テンプレートとマス目の種類は `<select>` です。** React の state を動かすには、
   ネイティブの value セッターを呼んでから change イベントを投げます。
   見本テキストの `<textarea>` も同じ扱いが要ります。
3. **なぞって選ぶ操作は、マス目の座標を取ってから実際にドラッグします。**
   同じ文字が複数のマスにあるので、何番目のマスかを指定しないと、
   意図しない広い範囲が選ばれます。

### 撮影環境について（正確を期すための記録）

- 撮影に使った環境は `fonts.googleapis.com` へ到達できなかったため、アプリが指定している
  Zen Maru Gothic（画面の書体）と Klee One（マスの中の書体。教科書体が無い端末での代替）を
  **端末にインストールした状態で撮っています。** アプリ側は一切変更していません。
  先生の端末で本番のアドレスを開いたときと同じ見た目です。
- `17-data-modal.png` の Google ドライブ同期の欄は「初期設定が必要です」と表示されています。
  これはビルド時に `VITE_GOOGLE_CLIENT_ID` を渡していないためです。
  **公開サイト側でこの変数が登録されている場合、実際の表示は「Google でログインして同期」の
  ボタンになります。** その場合はこの 1 枚を撮り直してください。記事本文はどちらの状態でも
  読めるように、同期は「学校で一度だけ設定が必要な機能」として書いてあります。

## 7. 文体について踏襲したこと

連載「教室で使えるかもしれないもの作り」の書き方に合わせています。

- 太字・斜体・表・区切り記号（→ ／ ： ▲ ▶）を使っていません。Markdown は見出しだけです
- 箇条書きは手順のところだけ。それ以外は文章で書いています
- 絵文字は見出しのみ。本文には入れていません
- 専門用語を日常の言葉に置きかえています。デプロイ、ローカルストレージ、CSP といった言葉は
  出さず、「公開の設定」「使っている端末のブラウザの中だけ」「アプリ側の設定で禁止しています」
  と書いています
- **教室での出来事を実体験としては書いていません。** これは作者の実践記録ではないので、
  「使ってみたら子どもたちが〜」という書き方は避け、「こうなればいいと思って作った」
  「〜だと思います」で止めています。実際の授業での様子は、書き手の方で足していただく想定です
- 効果を言い切っていません。「〜が期待できます」「〜だと思います」の形にしています
- 導入のメリットは「三つのいいことが期待できます。」から始めて、一つ目・二つ目・三つ目と
  段落で続ける型です
- 結びは #9 と同じ「一歩踏み出そうとする先生を、私はいつでも全力で応援しています。」です
